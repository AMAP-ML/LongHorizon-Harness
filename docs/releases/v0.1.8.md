# v0.1.8 — Resume approvals, role isolation, and output reliability

Released 2026-10-21. This patch release includes the fixes merged after v0.1.7 and a configurable closing-reply timeout.

## Fixes and improvements

- **Resumed-run approvals:** a resumed historical run no longer inherits `managed=false` and rejects approvals with HTTP 409. Continuing a run preserves its workspace, run ID, and round ledger. [#92](https://github.com/AMAP-ML/LongHorizon-Harness/pull/92), fixes [#83](https://github.com/AMAP-ML/LongHorizon-Harness/issues/83).
- **Manager routing:** accept backtick-wrapped `Next:` routes and routes immediately followed by a `Task:` / `任务:` section. Prefix traps and undelimited prose remain invalid, avoiding accidental routing. [#85](https://github.com/AMAP-ML/LongHorizon-Harness/pull/85), fixes [#80](https://github.com/AMAP-ML/LongHorizon-Harness/issues/80).
- **Claude Code MCP isolation:** every role now passes `--strict-mcp-config`. User/project MCP registries are no longer loaded implicitly; explicit `--claude-mcp-config` or `LH_HARNESS_CLAUDECODE_MCP_CONFIG` configurations remain supported. If you relied on an implicitly loaded MCP server, configure it explicitly after upgrading. [#75](https://github.com/AMAP-ML/LongHorizon-Harness/pull/75), fixes [#74](https://github.com/AMAP-ML/LongHorizon-Harness/issues/74).
- **DeepSeek output encoding:** emit ASCII-escaped JSONL so Unicode model output survives legacy stdout encodings losslessly after JSON decoding. Unicode preparation/launch diagnostics no longer prevent structured errors from being emitted. [#82](https://github.com/AMAP-ML/LongHorizon-Harness/pull/82), fixes [#78](https://github.com/AMAP-ML/LongHorizon-Harness/issues/78).
- **CLI output decoding:** tolerate invalid bytes in agent version/help probes, model discovery, and npm helper output instead of crashing subprocess readers. [#71](https://github.com/AMAP-ML/LongHorizon-Harness/pull/71), fixes [#64](https://github.com/AMAP-ML/LongHorizon-Harness/issues/64).
- **Accurate defaults:** both READMEs now document 25 rounds and 300-second Manager/Auditor episode budgets. [#44](https://github.com/AMAP-ML/LongHorizon-Harness/pull/44), [#92](https://github.com/AMAP-ML/LongHorizon-Harness/pull/92).

## Configure the final reply timeout

The closing reply now has its own optional budget:

```toml
[run.timeouts]
final_response = 1200
```

Or override it for one invocation:

```bash
lh-harness run --task @task.md --final-response-timeout 1200
```

When unset, the existing Manager-derived budget clamped to 60–180 seconds is retained. A timed-out or failed closing reply does not invalidate completed audits; regression tests verify that the completed report and round evidence survive. Unknown configuration keys still produce errors. This does not claim to resolve every terminal-state/report-loss scenario in [#76](https://github.com/AMAP-ML/LongHorizon-Harness/issues/76).

## Upgrade and resume

Stop active workers before upgrading, then use the command matching your installation:

```bash
# pip installation
python -m pip install --upgrade lh-harness==0.1.8

# uv tool installation
uv tool upgrade lh-harness

lh-harness --version
```

Restart the Web service with the same runs root and workspace root. Existing run directories remain usable; select **continue** to reuse the same run and round ledger. A worker already stuck with the old ownership flag must be stopped and resumed after the service is upgraded; updating the package does not change an already-running process.

## Platform status

**Native Windows execution remains blocked by POSIX-only control-bus/supervisor primitives.** The encoding fixes in this release do not constitute full native Windows support. Use WSL2 with both lh-harness and the agent CLI installed inside Linux; platform work remains tracked in [#70](https://github.com/AMAP-ML/LongHorizon-Harness/issues/70). MCP server integration and dynamic executor tiers are not included in this release.

v0.1.8 是修复版本，包含：

- 修复历史任务恢复后继承 `managed=false`，导致审批请求返回 HTTP 409 的问题；继续运行仍沿用原 workspace、run ID 和轮次记录。
- Manager 路由支持反引号包裹和与 `Task:` / `任务:` 写在同一行的格式，减少无效协议纠正轮次。
- Claude Code 各角色启用 `--strict-mcp-config`，不再隐式加载用户或项目的 MCP server。需要使用的服务请通过 `--claude-mcp-config` 或 `LH_HARNESS_CLAUDECODE_MCP_CONFIG` 显式配置。
- 修复 DeepSeek 在非 UTF-8 输出流下写入 Unicode 内容失败的问题，并让 CLI 探测、模型发现及 npm 辅助调用容忍非预期编码字节。
- 新增 `[run.timeouts] final_response` 和 `--final-response-timeout`，可单独提高最终回复的超时上限。未设置时保留原有 60–180 秒行为；最终回复失败不会撤销已经完成的验收。#76 的其他报告丢失场景仍需进一步复现。
- 更正文档中的默认值：最大轮数为 25，Manager/Auditor 的单次超时为 300 秒。

升级前请先停止正在运行的 worker，再使用上方 pip 或 uv 命令升级。重启 Web 服务时保留原来的 runs root 和 workspace root，选择 **continue** 继续原有任务。已经卡住的旧进程需要在升级后重新恢复，安装新版本不会自动修正运行中的进程。

**本版本仍不支持原生 Windows 全流程运行。** 请使用 WSL2，并在 Linux 环境内安装 Harness 和 agent CLI；完整支持统一在 #70 跟踪。MCP server 集成和动态 Executor 分档不包含在此次发布中。

发布前验证：Python 测试 **458 项通过**，前端测试 **61 项通过**；TypeScript 检查、Web 构建、wheel/sdist 元数据和内嵌前端检查均通过。未进行真实模型调用或原生 Windows 全流程测试。
